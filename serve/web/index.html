Настройки модели

Модель

Один сервер обслуживает несколько моделей: в каждый момент загружена одна, переключение завершает текущую и поднимает выбранную (загрузка 30–40 с и больше — зависит от размера). Список берётся из basalt_config.json. Поля ниже относятся к выбранной модели; серые пометки — то, что она не поддерживает (движок отвечает на это без загрузки).

Путь к файлу .basalt относительно конфига (или абсолютный): в нём лежат веса, токенизатор, шаблон чата, драфтер, vision-проектор и параметры сэмплинга по умолчанию. Имя файла — единственное обязательное поле модели.

Имя, которым модель называется в GET /v1/models и в поле model запроса, — в том числе во вкладке «Чат». Если поле пустое, берётся имя из файла. Полезно, когда у двух сборок одной модели должны быть разные имена.

Моделей в одном конфиге может быть сколько угодно — они обслуживаются по очереди (роутер завершает одну и поднимает следующую). Две модели на одном GPU одновременно загрузить нельзя: под них нужны разные GPU через gpu. Чтобы поставить Flash-Next рядом с Qwen3.8-27B, добавьте запись, укажите её файл, а поля ниже (контекст, KV, vram-elastic и прочие) задайте уже для неё — настройки движка хранятся в записи модели и не смешиваются.

Обслуживание

Выгрузка освобождает VRAM модели для других программ — следующий запрос загрузит её снова. «Освободить VRAM» уменьшает резерв памяти драйвера между запросами, «Вернуть VRAM» — возвращает стартовое значение из vram-reserve-mib. Плотная модель (как Qwen3.8-27B) отдаёт память только выгрузкой; у моделей-«смесей экспертов» (Flash-Next) ту же роль играет vram-elastic.

Параметры движка

Значения записываются в basalt_config.json; изменения контекста, KV, vision и порта вступают в силу после «Сохранить и перезапустить». Перед каждой записью копия конфига сохраняется в basalt_config.json.bak. Пустое поле = значение по умолчанию. Параметры генерации (temperature, top_p и прочие) задаются во вкладке «Чат» и применяются к каждому запросу без перезапуска.

Контекст и KV

Сколько токенов сервер держит в памяти (промпт + история + ответ). Больше — длиннее диалоги и документы, но KV-кэш растёт линейно и занимает VRAM/RAM. Загрузка модели тоже становится дольше. Для Qwen3.8-27B обученная длина — 131 072; выше неё нужен RoPE-скейлинг, точность падает.

KV-стриминг: N первых позиций каждого слоя внимания живут в VRAM, остальные — в закреплённой RAM и читаются по шине на каждый токен. Позволяет держать 131k контекста на 24 ГБ VRAM, но скорость декодирования падает тем сильнее, чем дальше позиция от N. 0 = выключено (весь KV в VRAM — быстро, но контекст ограничен объёмом карты).

Точность хранения ключей/значений внимания. fp16 — исходная точность модели; int8 сжимает вдвое (почти без потерь качества, рекомендуется); q4_0 и k8v4 сжимают сильнее, чуть снижая точность, и несовместимы с kv-resident.

Слоты и ввод

Кодировщик изображений. off — только текст. dynamic — кодировщик внутри движка, в простое VRAM не занимает, картинка кодируется за ~0.8 с. Номер GPU — отдельный процесс-сайдкар навсегда занимает ~2.2 ГБ VRAM из кэша экспертов. cpu — без VRAM, но заметно медленнее.

Сколько запросов сервер обслуживает параллельно. Память под контекст делится между слотами: 4 слота по 131k требуют вчетверо больше KV — включайте slot-full-context и следите за памятью. Отвечает быстрее в многопользовательской работе, но в одиночной оставьте 1: один слот получает весь контекст.

Выключено: max-context делится между слотами parallel (4 слота → по 32 768 токенов). Включено: каждый слот получает весь max-context, и KV-кэш занимает в N раз больше памяти. Нужно, когда несколько клиентов работают с полным контекстом одновременно.

Память

Сколько VRAM сервер оставляет свободной для системы, графики и рабочего стола. Слишком мало — драйвер начнёт выгружать память и всё замедлится; слишком много — кэш экспертов окажется меньше и часть работы уйдёт на CPU. Минимум 256 МиБ.

Сколько оперативной памяти оставить системе. Выше резерва движок размещает экспертов в RAM; ниже — начинает парковать разговоры и может тормозить ожиданием памяти. 2048 МиБ — разумный минимум, 0 полностью отключает защиту (может привести к свопу).

Кэш разговоров

Бюджет на «припаркованные» разговоры: сервер держит состояние недавних диалогов, чтобы новый запрос не перечитывал весь промпт. Экономит секунды на длинных системных промптах. 0 — выключено (каждый запрос читается с начала).

Дисковый бюджет того же кэша: разговоры переживают выгрузку модели и перезапуск сервера. Полезно, если работаете с одним длинным документом или проектом. Каждый файл привязан к модели и настройкам, при несовпадении удаляется.

Генерация по умолчанию

Сколько токенов модель может потратить на «размышления» перед ответом, если запрос не задаёт своё значение. Больше — глубже рассуждения на сложных задачах и медленнее ответ. 0 — отдать решение шаблону модели. В веб-чате это можно задать на каждый запрос отдельно.

Резерв вывода под закрытие размышлений и сам ответ: auto подбирает его от длины запроса. Мало — ответ может обрезаться сразу после размышлений; число — жёсткий резерв токенов.

Случайность генерации по умолчанию для запросов, не задающих свою. 0 — детерминированно (один и тот же ответ), 0.7–1.0 — живой текст, выше 1.2 — растёт риск бессвязности. В чате значение можно менять на каждый запрос.

Отбор из ядра вероятностей: модель выбирает из минимального набора токенов, чья суммарная вероятность ≥ p. Ниже — предсказуемее и суше, выше — разнообразнее. 0.9–0.95 — обычный диапазон.

Жёсткий предел: выбор только из k самых вероятных токенов. Отсекает редкие «мусорные» варианты, но при слишком малом k ответ становится шаблонным. 20 — сбалансированное значение.

Спекулятивное декодирование: черновик предсказывает до N токенов вперёд, модель проверяет их одним проходом. Ускоряет генерацию в 1.5–3 раза, выход побитово совпадает с обычным. 0 отключает. Больше окон — выше выигрыш, но и выше шанс впустую проверенных токенов.

Эксперты (Flash-Next)

Держит кэш экспертов сегментами, чтобы команда «Освободить VRAM» могла отдать память другой программе и забрать её позже. Работает только на Flash-Next — у Qwen3.8-27B (плотная, без экспертов) флаг игнорируется; на ней VRAM освобождают выгрузкой модели. Небольшой налог на скорость декодирования, зато игры и рендер перестают падать из-за нехватки VRAM.

Сколько блоков экспертов держать резидентно в VRAM и считать на GPU. auto берёт всё, что влезает после весов, сессии и резерва. Ручное число полезно, когда нужно осознанно сместить баланс «скорость против запаса VRAM»: больше — быстрее, меньше — свободнее карта.

Держать экспертов, не поместившихся в VRAM, в закреплённой оперативной памяти (читаются по шине), а не на диске. Это главный рычаг скорости для «смеси экспертов» на вашей машине: с ним эксперты считает CPU из RAM, без него — читает с SSD по 4 КиБ, и генерация заметно замедляется. Если RAM не хватает, движок сам переходит на файловый mapping. Только Flash-Next.

Хранить RAM-копию экспертов не в самой памяти, а в отображённом файле: системе легче освобождать такую память под другие программы, но чтения идут через файловый кэш и могут упираться в диск. Включайте, когда RAM в обрез (у вас 31 ГБ) и нужно оставить запас системе. Только Flash-Next, взаимоисключающе с обычным resident-experts.

Сколько оперативной памяти максимум отдать под экспертов в RAM (самые «горячие» первыми). Пусто — движок берёт всю свободную RAM сверх резерва. Ограничьте, если рядом работает что-то ещё и не хочется уходить в своп. Только Flash-Next.

Какую часть экспертов при обработке промпта (длинного текста) считает CPU, а не GPU. Выше — длинный промпт читается быстрее, если экспертов всё равно нет в VRAM; ниже — вся работа на карте. Значение фиксировано, поэтому результат не «плавает» от запуска к запуску. По умолчанию 0.6. Только Flash-Next.

Адаптивный ярус: сколько самых «востребованных» экспертов за один раунд переносится в VRAM вместо самых редких. Больше — быстрее подстраивается под смену темы, но тратит шину на перекладывание. 0 полностью отключает адаптацию. По умолчанию 96. Только Flash-Next.

Сервер

TCP-порт на 127.0.0.1. После смены обновите адреса у клиентов (OpenCode, Hermes) и открывайте панель по новому адресу. Проверьте, что порт не занят другой программой.
